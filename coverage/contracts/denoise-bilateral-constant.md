# Constant-border bilateral filtering

The native Python path admits ordinary aligned C-order native-endian float32 or float64 ndarrays with no dtype metadata, rank-2 grayscale or rank-3 RGB with `channel_axis=-1`. Spatial dimensions are 2–512. Input elements are finite in [0,1], with a maximum of at least 1/256 for nonconstant filtering. A constant admitted array returns itself. Constant-mode `cval` is in [0,1]. Spatial sigma is in [0.25,4], effective color sigma in [1/256,1] and bins in [4,65,536]. Odd explicit windows in [5,25] and the original default formula are admitted. Other inputs use the existing compatibility policy, including other modes, signed values, integer conversions, unusual strides or channel placement, and exceptional parameters.

NumPy computes the converted-field global standard deviation when color sigma is omitted and prepares both lookup tables with the original expressions and work dtype. The spatial grid starts at Python `(-window)//2` and has `(window+1)^2` entries. The kernel indexes the flattened table with row stride `window`. The constant sampler returns typed `cval` outside the image. The C++ kernel reduces the typed Euclidean color distance in channel order, truncates the lookup coordinate and clamps it to the last valid bin. It accumulates values and weights in row-major stencil order and divides without replacing a zero denominator. The Python output uses the original squeeze semantics. The binding requires round-to-nearest for the native prepared calculation and releases the GIL while the serial stencil runs. A separate SIMD or internal worker path is outside this scope.

The installed prepared C++ API accepts aligned, complete, disjoint typed HWC buffers and caller-provided lookup tables under the bounded domain. The SDK validates geometry and declared extents before any write. The Python path uses the existing owner/span checks. The prepared SDK caller keeps its input and LUT buffers live and immutable through filtering.

They preserve exact output and lookup hashes separately because upstream NumPy precision differs across these runtimes. Both represent 28 safe contract cases and six fixed full-call recipes.
