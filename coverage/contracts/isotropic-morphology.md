# Isotropic binary morphology

The four public calls use upstream's `(image, radius, out=None, spacing=None)` signature. The native scope is an ordinary, aligned C-order NumPy boolean ndarray with no dtype metadata, rank 1–3, nonempty axes of at most 65,536 elements and a total size of at most 67,108,864 elements. The native radius accepts Python float, including infinities and quiet NaN, and Python integer within 2^53. Sampling accepts the default, a scalar, or a length-rank tuple or list of Python numbers in [1/65536, 65536]. The optional native `out` is an ordinary writable boolean ndarray of the same shape and layout, with no dtype metadata. The binding verifies the input and output storage spans.

The admitted label-expansion EDT computes the distances to true sites for dilation or to false sites for erosion. Dilation uses distance less than or equal to radius. Erosion uses distance greater than radius. A mask with no sites uses the outside feature coordinate `(-1, 0, ...)` used by SciPy. Opening computes erosion followed by dilation. Closing computes dilation followed by erosion. Both composition stages use the supplied radius and spacing. The native path handles special radii without invoking the distance transform. Its temporary masks allow exact or partial overlap between input and `out`. The call returns the supplied output array after completion.

The native path is serial C++ from the Python binder through the distance transform. It does not consult an optional provider. The source files `isotropic_morphology.cpp` and `bind_isotropic_morphology.cpp` require strict floating-point compilation matching the expand-labels leaf. The SDK header has a smaller buffer contract with aligned, complete, disjoint spans and normalized output bytes. The Python binder routes non-nearest rounding and signaling NaN through the compatibility path. Input subclasses, metadata-tagged or numeric arrays, unsupported sizes, alternate layouts, malformed or unsupported radius and spacing, and other output arguments use the existing scikit-image fallback policy. That compatibility path preserves upstream errors and supports the original NumPy/SciPy providers.
