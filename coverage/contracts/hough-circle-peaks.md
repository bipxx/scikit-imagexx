# Bounded circular Hough peaks

The bounded route accepts ordinary aligned C-order float64 volumes with 1 to 16 planes and spatial extents from 1 to 256. It accepts a matching ordinary positive native index radius vector, nonnegative integral spacing up to 32 with x spacing at most the plane width, finite nonnegative or default thresholds, and nonnegative integral or unlimited caps. It uses the existing compatibility policy for other inputs, including empty axes, mismatched or non-index radii, unsupported layouts, negative or nonfinite votes, and votes close enough to underflow the default half-maximum threshold.

The local C++ stage computes constant-zero separable maxima and row-major Boolean components. It uses strict thresholding, rounds centroids to even and reads the surviving vote at that centroid. It skips row zero during suppression and mirrors rows when suppression wraps x. The exposed SDK operation returns its own vector of local peaks before ranking or cross-radius pruning.

NumPy orders the active per-plane cap and the full set of peaks. The normalized path orders by raw vote divided by radius while returning the raw vote. The default spacing branch keeps the original descending array views and negative strides. An empty result before global pruning returns four float64 empty views. The nondefault spacing branch returns owned arrays of votes and index coordinates and radii, even when the total cap is zero. SciPy supplies the radius query for this branch and the following rectangle test keeps the original order. The retained (2, 3) corner observation would differ with a rectangle alone.

The frozen stock fixture contains exact per-profile data and metadata for 29 cases. Keep all four fixed prepared-volume comparisons and exact profile-specific ordered results. Shared integration, genuinely installed ownership and SDK, and one-thread speed remain separate gates.
