# Retained sparse correlation

`filters.correlate_sparse` now has a C++17 implementation with native border padding, cache-sized product/addition tiles, explicit AVX2 and optional global workers. It preserves input-to-floating promotion, the inserted corner term, ordered rounded products/additions, dtype tags, memmap result class and floating warning/error behavior. Supported real inputs, modes and explicit fallback boundaries are listed in the main README. This remains a partial input contract, not whole-library parity.

[Successful paired Linux/Windows run](https://github.com/bipxx/scikit-imagexx/actions/runs/39801362511) measures source `4972713`, product SHA256 `99a00546fb6c9ebfd238b5944e52254a7fd4f520f8ac7ec4ac9a8c11593f4a48`, against scikit-image 0.26.0 and exact initial native package `b707c0c`. Both packages pass every timed case exactly on NumPy 2.5.4, with fallback disabled. The initial package has wider-contract defects described in the [initial experiments](sparse-initial.md); it is a performance comparator, not the retained implementation.

The corpus has 45 cases at global worker limits one/four on each OS, seven randomized samples, seed 7213 and size 512. Allocation, conversion, padding and Python dispatch are included; reference pools are fixed at one. Images below the native 256×1024-element activation threshold remain serial even when the limit is four. Both current and baseline wheels/packages, binary hashes and source fingerprints are preserved in the run artifacts. All 180 measured rows and every raw sample are retained below.

One-worker geometric means are **1.938x Linux / 2.258x Windows** over scikit-image and **1.105x / 1.053x** over the initial native package. Every one-worker case beats upstream in this corpus: the slowest is 1.290x on Linux and 1.223x on Windows. These are runner-specific results, not guarantees for other hardware, inputs or versions. With a four-worker limit, geometric means are 1.904x/2.667x over upstream.

The initial full-row padding map was allocated for every input column although only its halo entries were used. The retained path maps only border entries and computes each tile’s row addresses once for all taps. Long 1-D cases improve **3.29–6.62x Linux / 1.42–2.34x Windows** against the initial package. Runtime scalar-comparison profiling preserves legacy NumPy signaling-cast behavior while avoiding unnecessary modern-runtime work.

Adverse controls are retained: Linux float64 reflect is **0.683x** baseline/current and uint8 reflect **0.801x**; Windows float64 strided is **0.882x**. Linux reflect samples are bimodal, but the recorded medians still represent regressions against that initial package and are not discarded. Linux float32 identity at the four-worker limit is **0.969x** upstream/current. Several other controls are slightly slower than the initial native package. Padding/allocator interactions, layout normalization and small-copy parallel overhead remain optimization targets.

Validation: the exact candidate wheels pass **9,890 scoped Windows tests in each SIMD mode**, including sparse/hysteresis/API/dtype metadata, and **3,556 dedicated minimum-NumPy tests in each mode**. Native release, dynamic-team, portable and ASan/UBSan normal/dynamic checks each pass 2/2. A further large 3-D native check verifies serial/parallel output and overflow-status aggregation under all five native configurations. The measured product fingerprint is unchanged by that additional test. Dedicated cases cover real dtype widths, full-range integers, all supported padding aliases, singleton/empty/storage layouts, broadcast-independent kernels, NaN/infinity/signaling values, warning/error policies and worker boundaries. Full follow-up CI remains in progress.
