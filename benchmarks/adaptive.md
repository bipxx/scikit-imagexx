# Adaptive threshold initial checkpoint

Measured source: `85de559`; product fingerprint `4038874e0c5046b4ee86b4a3a1ebb329129fdebd5821754294c496b587d134f8`. Reference: original scikit-image 0.26.0; NumPy 2.5.4. This adds a partially native `filters.threshold_local` with the upstream Python signature. Gaussian, mean and median methods run C++; generic callbacks and unsupported exceptional inputs require explicit upstream fallback. It does not establish full scikit-image coverage.

The fixed 63-case corpus uses seed 1709, uint8/float32/float64, 512 by 513 images, 3/15 windows, contiguous/Fortran/reversed-strided storage, scalar offset, constant borders and tiny 3 by 7 inputs. Each OS ran one- and four-worker limits with seven randomized samples, 15 ms target batches and 20 ms cooldown. Allocation, conversion, validation and dispatch are included. Parity is checked before timing; fallback is disabled and reference thread pools are fixed to one. These GitHub-hosted runner results are not the historical local i7-12700K whole-library checkpoint. The initial harness records OS/runtime and AVX2 availability but omits a CPU model.

[Exact packages, wheels and raw samples](https://github.com/bipxx/scikit-imagexx/actions/runs/39775834198) are archived before tuning. Every reported JSON retains all raw samples, including regressions. No paired improvement over an earlier native implementation is claimed.

Scoped validation: Windows passes 4,984 adaptive/API cases in each SIMD mode. Linux/NumPy 1.24 passes 2,922 adaptive cases in each mode. Native release, portable (AVX2/OpenMP disabled), ASan/UBSan, and dynamic-team checks pass 2/2. Tests cover every 3x3 binary neighborhood, borders, promotion, dtype tags, empty/scalar/N-D inputs, and storage layouts. Generic-rank zero-stride behavior and version-specific SciPy 1-D rank dispatch are preserved.

Speedup is original/current, so values below 1 are slower. Mean remains a bottleneck: Windows one-worker mean is slower in aggregate; tiny mean calls on both OSes take about twice the upstream time, and Fortran layout adds copying cost. Profiling 5,000 tiny mean calls attributes most time to Python preparation rather than the native filter, including repeated error-policy/dtype checks. Large-window median and some four-worker cases also remain slower. These results establish the preserved baseline for subsequent optimization; they do not satisfy a per-case performance win.
