Table times and ratios are rounded; the raw report retains full precision. These are ordinary uint8/float32/float64 square images using the default `block_size=2`, `func=np.sum` and `cval=0`. Seven warmed paired rounds run on a fresh offline measurement host with one global worker; worker assertions and before/after identities passed. Timings include the public preparation, padding decision, owned sum and allocation. These divisible sizes require no padding copy. Input generation and the frozen per-block checker run outside timing. Only the new six-case benchmark ran; eleven earlier standalone timing steps were skipped.

The source-first matrix has 72 specs: 43 assigned to owned default sums, 22 explicit primitive-provider cases and seven intake-error cases. These are prospective route partitions, not outcome counts: the original captures returned 61 results and 11 errors per profile. The private components passed 580 public and 88 shared checks across modern/minimum normal/scalar modes. All 43 native routes retained their strict forwarding traps. Half accumulator stores follow NumPy iterator segments, output allocation follows the source zero/unit-stride axis ordering, and the padding metadata check avoids the generic reduction wrapper. Initial failures remain retained; fixtures, route assignments and the per-block `2*gamma_m*S` plus half-rounding allowance were unchanged.

The installed Release passed thirteen normal/scalar focused pairs (3,108 checks), the complete color suite (1,848 per mode; 3,696 total), 1,381 smoke checks and the entire 1,612-test histogram-matching suite. Source registry coverage is 227 native-partial image APIs plus three metadata functions (230 total). Native normal/scalar and both ASan/UBSan modes each passed 527,151 controls. Separate bounded private portable/no-OpenMP normal/scalar runs each passed 263,578 controls, including worker-four refusal with default worker one; their outputs and FP status matched the retained worker-one baseline. Those counts include two private harness controls beyond the tracked 263,576-control cohort.

Ordinary default sums own typed C++ block arithmetic and output partitioning. NumPy padding, block-view metadata, storage preparation and allocation remain providers. Native half sums currently require original padded native-endian, aligned C-contiguous storage and block volume no larger than `np.getbufsize()`. Other half layouts, reversed/swapped/unaligned storage and larger buffered reductions remain literal providers and open native-coverage work. Custom functions, reducer kwargs, complex padding and exceptional/type-frontier sums also retain explicit primitive providers without native sum credit. Platform NumPy integer-promotion rules, including modulo narrowing for NumPy 1 Windows results, are handled at the caller boundary; this packet does not claim Windows execution.

The authenticated wheel, sole installed core, complete package, SDK and source identities matched before and after measurement. Fourteen wheels included thirteen runtime dependencies. The host was x86_64 Linux with CPython 3.11.17, NumPy 1.24.4, SciPy 1.15.3 and scikit-image 0.26.0; a detailed CPU model was not captured. The measured source already included the kept RGB uint8 optimization, but these timings measure block reduction only. This is a first original-library comparison, not a prior-C++ gain or full supported-profile qualification. Accepted full-profile image coverage remains 203.
